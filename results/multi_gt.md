# 3つの正解定義による比較（ツールの精度は「正解の定義」に依存する）

6リポジトリ（gin, cobra, hugo, frp, gorm, ollama）で、各ツールを**3種類の正解(GT)**に対して評価。
`node ../compute_multi_gt.js` で再現。name 一致。

## 3つの正解定義
| 正解 | 定義 | コマンド |
|------|------|---------|
| **all** | モジュールビルドリスト全体（テスト依存・推移依存を含む） | `go list -m all` |
| **imported** | 実際にコンパイルに取り込まれるモジュール | `go list -deps ./...` |
| **direct** | go.mod の直接依存（`require` の非 indirect） | `go mod edit -json` |

（frp は `go list -deps` が失敗したため imported は5リポジトリ平均、all/direct は6リポジトリ平均。）

## 知見（本研究の中心的主張）
1. **「最も正確なツール」は正解の定義によって入れ替わる**。
   - 正解=**all（ビルドリスト全体）** なら **syft が最良**（F1 69.8）。syft/trivy は go.sum 等から
     推移依存まで読むため。
   - 正解=**imported（実際に使うモジュール）** なら **cdxgen が完璧（F1 100.0）**。cdxgen は
     imported 集合を*正確に*出力していた（gin18, hugo106, ollama71, gorm3, cobra4 が GT と完全一致）。
2. **全ツールが imported に対して Recall 100%**。つまりどのツールも「実際に使うモジュール」は
   取りこぼさない。`all` で Recall が低く見えたのは、テスト専用・未使用の推移依存（= imported に
   含まれない）を数えていたため。
3. **syft/trivy は imported 正解だと Precision が急落（45〜50%）**。これは「過剰報告」ではなく、
   imported に含まれない（がビルドグラフには在る）モジュールまで報告しているため。用途次第で
   これは長所（脆弱性の見落とし防止）にも短所（ノイズ）にもなる。
4. **したがって "accuracy" は単独では語れない**。SBOM ツールは「どの依存定義を対象にするか」を
   明示すべきで、評価もその定義に対して行うべき、というのが本研究の提言。

## 用途別の推奨（提案）
| 目的 | 適した正解定義 | 適したツール |
|------|----------------|--------------|
| 脆弱性を漏れなく洗う（テスト依存含む） | all | **syft**（最高 Recall） |
| 配布物に実際に含まれる依存を正確に把握 | imported | **cdxgen** / cyclonedx-gomod |
| 直接依存のみ管理 | direct | cdxgen / cyclonedx-gomod |
