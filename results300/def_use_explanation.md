# 3つの正解の作り方と意味（def-use と go list の解説）

## 1. 3つの正解を作るコマンド
```bash
# all（モジュールグラフ全体。従来の正解。Yu らの pip install 相当）
go list -m all

# imported（実際にビルドに取り込まれる＝コードが本当に使うモジュール。＝def-use の実装）
go list -deps -f '{{with .Module}}{{.Path}} {{.Version}}{{end}}' ./... | sort -u

# direct（go.mod に直接宣言した依存。// indirect が付かないもの）
go mod edit -json     # 出力 JSON の .Require のうち "Indirect": true でないもの
```

## 2. コマンドの読み方（imported の行）
`go list -deps -f '{{with .Module}}{{.Path}} {{.Version}}{{end}}' ./... | sort -u`

- `go list` … パッケージ／モジュールの情報を表示する Go 標準コマンド
- `-deps` … 対象パッケージが import している**依存も再帰的に**すべて含める
- `-f '...'` … 出力の書式（テンプレート）
  - `{{with .Module}}...{{end}}` … 「そのパッケージがモジュールに属するなら…」（標準ライブラリはモジュールが無いので空になる）
  - `{{.Path}} {{.Version}}` … モジュール名とバージョンを出力
- `./...` … このフォルダ以下の**全パッケージ**（自分のプロジェクト）
- `|`（パイプ）… 左の出力を右のコマンドへ渡す
- `sort -u` … 行を並べ替え、**重複を削除**（`-u` = unique）。
  `go list -deps` は「1パッケージ＝1行」で出力し、1モジュールは多数のパッケージを含むため
  同じモジュール名が何度も出る。`sort -u` で「1モジュール＝1行」にまとめる。

## 3. `go list -m all` と `go list -deps` の違い（動作）
| | `go list -m all` | `go list -deps ./...` |
|---|---|---|
| `-m` | **モジュール**を対象 | （`-m` 無し）**パッケージ**を対象 |
| 何をする | モジュールシステムが追跡する**グラフ全体**を列挙 | コードの **import を再帰的にたどる**（実際に使う物） |
| テスト専用・未使用も含む？ | **含む** | **含まない**（実際にコンパイルされる物だけ） |
| たとえ | 「買い物リスト全部」 | 「実際に料理に使った材料」 |

## 4. 具体例（spf13/cobra, Linux 上）
`go list -m all` は **7** モジュール、`go list -deps` は **5**（実依存4＋cobra自身）。
差の2つ＝「宣言されているが実際には使われない」依存:

- **github.com/inconshreveable/mousetrap** … **Windows 専用**。Linux/Mac ではビルドに取り込まれない。
- **gopkg.in/check.v1** … **テスト専用**の依存（依存先のテストで使われるだけ）。

→ Linux でこの2つを SBOM に載せて脆弱性報告すると、**実際には実行しないコードなので誤検知**になる。

## 5. なぜ重要か（def-use 解析）
Yu ら（DSN 2024）は「`go.mod` 等の**宣言**を読むだけだと、宣言されたが実際には使われない依存まで
報告し、**脆弱性の誤検知**を生む。各ライブラリが実際に使われているか判定する **def-use 解析**の
導入を今後の課題として推奨する」と述べた（実装はしていない）。
本研究の **imported（`go list -deps`）= この def-use を Go で実装したもの**である。

## 6. 教授への説明（そのまま使える）
> 先行研究 Yu ら（DSN 2024）は、SBOM ツールが宣言を読むだけなので「宣言されたが使われない依存」
> まで報告し脆弱性の誤検知につながると指摘し、各ライブラリが実際に使われているかを判定する
> def-use 解析の導入を今後の課題として提案した（未実装）。本研究はこれを Go で実装し、
> `go list -m all`（全グラフ）に加えて `go list -deps`（実際に使う依存＝imported）を正解として
> 4ツールを評価。「最も正確なツールは正解の定義で入れ替わる」こと、各ツールの取りこぼしの
> ほぼ全ては「実際には使われない依存」で真の見逃しは1%未満であることを約190〜216リポジトリで
> 定量的に示した。
