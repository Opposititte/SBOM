# 300リポジトリ規模：3つの正解定義による比較

awesome-go 先頭300件のうち Go モジュールの repos で、各ツールを **3種類の正解(GT)** に対して評価。
`RESULTS=results300 node ../compute_multi_gt.js` で再現。name 一致、macro 平均。

## 3つの正解定義（おさらい）
```
direct（go.mod の直接依存）⊆ imported（実際にコンパイルされるモジュール）⊆ all（モジュールグラフ全体）
```
- **all** = `go list -m all`（テスト依存・未使用の推移依存も含む）
- **imported** = `go list -deps ./...`（実際にビルドに取り込まれる＝コードが実際に使う依存）
- **direct** = `go mod edit -json` の require（indirect でない直接依存）

評価対象数: all=216 / imported=190（`go list -deps` が成功し非空のもの）/ direct も同程度。

## 知見（6リポジトリの結論が300規模でも再現）
1. **「最も正確なツール」は正解の定義で入れ替わる**（本研究の中心的主張、300規模で確認）。
   - 正解=**all** → **syft / trivy が最良**（F1 ≈71）。go.sum 等から推移依存まで読むため。
   - 正解=**imported** → **cyclonedx-gomod が最良**（F1 94.0）、cdxgen が僅差（90.7）。
2. **全ツールが imported に対して Recall ≈96〜99.9%**。どのツールも「実際に使う依存」は
   ほぼ取りこぼさない。`all` で Recall が低く見えたのは、テスト専用・未使用の推移依存を
   数えていたため（ツールの欠陥ではなく正解定義の問題）。
3. **syft/trivy は imported 正解だと Precision が急落（50〜54%）**。imported に含まれない
   （がグラフには在る）モジュールまで報告するため。これは脆弱性網羅では長所、配布物の正確な
   把握では過剰報告。
4. **direct 正解では全ツールの Precision が低い（30〜51%）**。どのツールも直接依存以上を
   報告するため。direct は「宣言された依存」であり、ツールの出力対象とは普通ずれる。

## 用途別の推奨
| 目的 | 正解定義 | 推奨ツール |
|------|----------|-----------|
| 脆弱性を漏れなく洗う（テスト依存含む） | all | **syft**（最高 Recall・F1） |
| 配布物に実際に含まれる依存を正確に | imported | **cyclonedx-gomod / cdxgen** |

## 結論（論文向け）
SBOM ツールの "accuracy" は単一の数値では語れない。**評価は「対象とする依存定義」に対して
行うべき**であり、ツールは自身がどの定義（all / imported / direct）を出力するのかを明示すべき。
本研究は Go エコシステムでこれを 216/190 リポジトリ規模で定量的に示した。
